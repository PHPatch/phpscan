# Changelog

The package version in `pyproject.toml` is 1.5.0. Signed GitHub
Releases start with 1.4.4; earlier history below is taken from
the git log.

## Unreleased

- VERSION HIDDEN verdicts (status `indeterminate`) now carry
  owner self-check guidance instead of ending at "cannot be
  confirmed from outside": the JSON verdict gains a one-line
  `remediation` and a `next_steps` list (check the version
  server-side via `php -v`, the hosting panel, or a temporary
  phpinfo page that must be deleted immediately; verify it
  against the public advisory feed; upgrade or patch if it is
  end-of-life or vulnerable), and the text output renders the
  same steps as an "If this is your site" block, closing with a
  reminder that a hidden version is not evidence a site is
  vulnerable. Additive only — no verdict label or other
  verdict's text changed.

## 1.5.0 — 2026-10-30

- `phpscan hunt <webroot>`: read-only local compromise check.
  Known webshell fingerprints and filenames (c99, r57, FilesMan,
  b374k, WSO), backdoor idioms (request-input eval/assert,
  preg_replace /e, obfuscated decode chains), PHP files inside
  upload/media/cache dirs, double extensions, hidden PHP
  dotfiles, and mtime outliers — each finding graded
  critical/high/medium/low with remediation text; `vendor/`
  skipped unless `--include-vendor`. Indicators live in
  `phpscan/data/iocs.json` (patterns + filenames only; the
  known-bad hash set ships empty because no published hash list
  had verifiable provenance).
- External scan: existence-only checks for a short list of
  famous webshell paths, reported as `compromise_indicators`
  (indicative, not conclusive) and counted as actionable for
  the CLI exit code.
- Advisory database is now the full PHP core CVE set (700+
  advisories, branches 4.3–8.5), generated by
  `tools/build_core_db.py` from the NIST NVD CPE ranges
  cross-checked against the php.net ChangeLogs, instead of the
  single hand-maintained php2shell entry (which is preserved as
  a curated bundle). Verdicts aggregate every matching advisory:
  the headline is the most severe, `floor` names the branch's
  cumulative patched release, and a new `findings` list carries
  every match, including advisories with no fix for the branch.
- Public advisory feeds: `tools/build_feed.py` emits the
  database as JSON plus an Atom feed of the 50 most recent
  advisories (generated copies in `feeds/`), for hosting at
  stable phpatch.com URLs. `tools/refresh_advisory_db.sh`
  regenerates database + feeds in one cron-ready step.
- `phpscan audit <composer.lock|dir> [--offline]`: dependency
  audit of a composer.lock. Locked packages (dev dependencies
  included, flagged `dev`) are matched against the OSV API
  (Packagist; names + versions only, batched), a vendored
  snapshot of the FriendsOfPHP security-advisories database
  (`phpscan/data/friendsofphp.json`, refreshable via
  `tools/refresh_advisories.py`), and the CISA KEV catalog
  (`phpscan/data/kev.json`) for known-exploited flags. Version
  matching implements Composer constraint semantics with
  FriendsOfPHP branch scoping — an advisory listed for one
  release line does not fire on another. Every finding carries
  a `remediation` (the `composer update` command and the fixed
  version); unparseable ranges and non-release versions are
  reported as `unassessed`, never guessed. Exit codes 0/1/2
  (no findings / findings / usage or input error); `--offline`
  uses only the vendored snapshots.
- Test suite: fixed an order-dependent fake in the scan tests
  (a shared mutable class attribute made one test pass under
  unittest's ordering and fail under pytest's); the suite is
  green under both runners.

## 1.4.4 — 2026-10-30

- Actionable verdicts (`vulnerable`, `possibly_vulnerable`, `eol`)
  now carry a `remediation` field naming the upgrade that fixes
  them (distro builds point at the distro security tracker
  instead); patched verdicts carry none.
- README: `pip install git+https://github.com/PHPatch/phpscan.git`
  install path (verified by a clean-room venv install), and a
  "Scanned by phpscan" badge snippet.
- Installable console script: installing the package now provides
  a `phpscan` command; `-h` / `--help` print the usage text.
- Signed releases: artifacts are PGP-signed with the PHPatch
  Security key (see `SECURITY.md`), ship with an SBOM, and are
  built for PyPI trusted publishing (OIDC).
- Dockerfile + GHCR image workflow, and a companion GitHub Action
  (`PHPatch/phpscan-action`).
